Root-Cause Analysis — Why Each Metric Diverges

Faithfulness +0.253 RAGAS advantage

RAGAS Decomposes the answer into individual atomic claims and checks each one against the context separately. A claim passes if semantically similar text exists in the context. Final score = (claims supported / total claims). Partial credit is awarded per claim.
DeepEval Evaluates faithfulness holistically — one LLM call rates whether the full answer is grounded. Small models such as qwen2.5:7b tend to be stricter in this single-pass evaluation and penalise any ungrounded phrase in the whole answer.
Result RAGAS is more lenient because each claim is evaluated independently and partial credit is awarded. DeepEval's single-shot evaluation penalises any ungrounded phrase in the whole answer.

Answer Relevancy −0.166 DeepEval advantage

RAGAS Uses a novel reverse-generation approach: generates 3 synthetic questions from the answer, then computes cosine similarity between those synthetic questions and the original question. If the answer covers multiple aspects, the synthetic questions may drift from the original. Detailed answers get penalised.
DeepEval Makes a direct LLM judgment: "does this answer address this question?" — one call, binary-style reasoning. Small models are good at this direct comparison and reward answers that stay on-topic.
Result RAGAS penalises answers that are more comprehensive than the question requires. DeepEval rewards answers that stay on-topic.

Context Precision +0.059 — within noise

RAGAS Checks relevance chunk-by-chunk: each retrieved chunk is independently assessed for relevance to the question. Score is aggregated across chunks with rank-weighting.
DeepEval Evaluates the context set holistically in a single LLM call, asking whether the retrieved content as a whole is precise relative to the question.
Result Both frameworks roughly agree on retrieval precision. The small difference (0.059) is within noise range for a 6-question set and is likely attributable to prompting style rather than a real pipeline difference. When two frameworks agree, the signal is trustworthy.

Context Recall +0.490 — largest divergence

RAGAS Checks each sentence in the reference answer: can this sentence be attributed to the retrieved context? Attributability is checked via LLM with semantic matching. Score = attributable sentences / total sentences. Result: 1.000 = every sentence in every reference was found in the retrieved context.
DeepEval Checks whether the context contains enough information to generate the full expected output. qwen2.5:7b evaluates this as a holistic judgment and is stricter — it considers whether all specific facts and numbers are present, not just semantic attributability. Score: 0.51.
Result Most important divergence for practitioners. RAGAS recall=1.0 might give false confidence. RAGAS scores 1.000 because reference sentences are semantically present in the Zephyr context (chunk400 is large enough to contain full facts). DeepEval's stricter check (0.51) reveals the retriever only reliably surfaces all needed specifics half the time.

Why the Same Judge Model Produces Different Scores

Both frameworks used qwen2.5:7b (via Ollama, USE_LOCAL_JUDGE=1) as the judge model, yet produced very different scores — particularly on Faithfulness (+0.253) and Context Recall (+0.490). The judge model is only one component of the evaluation pipeline. The framework's prompting strategy, decomposition approach, and scoring aggregation method all affect the final number independently of which model answers the prompt. RAGAS constructs multi-step decomposition chains and sends multiple targeted sub-prompts to the judge; DeepEval sends fewer, simpler prompts and aggregates differently. This is why practitioners should run both frameworks and treat divergence as signal — not noise. If you only ran one framework, you would not know whether your score reflects your pipeline or the framework's evaluation lens.

Recommendation

Use RAGAS when you want a dataset-level benchmark and can tolerate more LLM calls. Use DeepEval when you are running LangSmith experiments, need per-question pass/fail in CI/CD, or want simpler LLM prompts that are more reliable with local models. When scores diverge significantly — as they do here on Recall (1.000 vs 0.510) and Faithfulness (0.833 vs 0.580) — investigate the root cause. The divergence itself is diagnostic information about how your system performs under different evaluation lenses, and understanding that divergence is more valuable than trusting either number in isolation.

Key Insights

1

RAGAS Recall=1.0 does not mean perfect retrieval. It means every sentence in the reference answer was semantically present somewhere in the 3 retrieved chunks. DeepEval's stricter check (0.51) reveals retrieval only reliably covers all needed specifics half the time. Do not mistake semantic attributability for factual completeness.

2

Framework methodology determines your score as much as your pipeline. The faithfulness delta of +0.253 is not noise — it reflects a genuine difference in how RAGAS (claim-level decomposition) and DeepEval (holistic single-call) prompt the judge. Changing your framework can move your score without changing your RAG pipeline at all.

3

For local models, simpler prompts win. DeepEval's single-call evaluation is more reliable with qwen2.5:7b than RAGAS's multi-step decomposition chain, which can fail mid-chain and return NaN. If you are constrained to local models, DeepEval's lower prompt complexity translates directly to more stable scores.

4

Use framework agreement as a trust signal. When RAGAS and DeepEval agree (Context Precision: 0.889 vs 0.830), you can be confident the metric reflects a real pipeline property. When they diverge (Recall: 1.000 vs 0.510), you need to understand why before trusting either number — the divergence is the finding, not a problem to dismiss.
