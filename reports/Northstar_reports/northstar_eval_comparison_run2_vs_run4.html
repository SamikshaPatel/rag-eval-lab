Verdict

Run 4 wins on reference-based accuracy: Correctness improved +0.05 (0.82 → 0.87), Completeness improved +0.07 (0.79 → 0.86), and Faithfulness improved +0.04 (0.67 → 0.71). The two persistent exception failures (NSB-023, NSB-024) are now fully resolved with correctness=1.00 each.

Run 2 holds an advantage on hallucination and precision: Hallucination score dropped from 0.53 → 0.44 in Run 4, and Contextual Precision fell by 0.05. The model stayed closer to the literal retrieved context when given a simpler prompt.

The core tradeoff: Prompt v2 makes the model smarter at applying policy rules (universal-rule inference, exception detection) but slightly less conservative about staying strictly within the retrieved text. Instructions that say "infer from universal rules" push the model to go beyond the literal context — which improves correctness but increases inferred claims the hallucination metric penalises.

NSB-034 root cause identified and fixed: All-zero scores in Run 4 were caused by multi-query retrieval over-triggering. The question mentions "user" and "administrator" — both tracked as role terms — so the retriever fetched role-definition chunks (section 1.1) instead of the session-control policy (section 8.2). The model abstained because the relevant fact was never in the context. Fix: multi-query retrieval now requires explicit comparison language in addition to two role names. Post-patch validation confirms the correct answer: "Within five minutes."

For a banking policy assistant, correctness and completeness matter most. Run 4 is the recommended configuration.

Key Insights

Prompt v2 fixed exception reasoning

NSB-023 and NSB-024 now score correctness=1.00. A single instruction with a worked example was enough for llama3.1:8b to reason through universal rules. The model now correctly identifies that "every international wire requires Dual Approval" is a universal constraint that overrides the amount-based threshold — without needing the rule to be stated literally in the retrieved chunk.

Multi-query retrieval partially fixed NSB-033

Both Viewer and User definition chunks are now retrieved by issuing a separate similarity_search per role name. Correctness improved from 0.00 → 0.80. Precision dropped slightly (0.33) because multi-query brings more diverse chunks alongside the two target definitions — a predictable tradeoff. Increasing k or adding a deduplication step could recover precision without sacrificing recall.

Faithfulness-hallucination tradeoff

Prompt v2 improved faithfulness (+0.04) but worsened hallucination (−0.09). This is not a contradiction: faithfulness measures whether claims are supported by the retrieved context, while hallucination measures whether the model introduces statements not literally present. Instructions that say "infer from universal rules" push the model to generate correct logical conclusions that go slightly beyond the literal text — raising both faithfulness (the inference chain is sound) and the hallucination penalty (the conclusion is inferred, not quoted).

NSB-034 root cause found and fixed

All-zero scores were not a judge failure — they were a retrieval bug introduced by the multi-query strategy. The question mentions "user" and "administrator", both role terms, so _get_contexts() ran per-role queries and fetched role-definition chunks (section 1.1) instead of the session policy (section 8.2). The model never saw the "five minutes" fact and correctly abstained. Fix: multi-query now requires explicit comparison language ("difference", "compare", "versus") alongside two role names before triggering. Re-running NSB-034 in isolation post-patch returned the correct answer: "Within five minutes." This is a good example of a retrieval bug masquerading as a generation failure — the all-zero pattern across every metric was the diagnostic clue.
